# T03 - Auth CTA Interception

> depends on: T02

## 보장할 동작

랜딩, 헤더, 공통 인증 버튼의 로그인/회원가입/시작하기 CTA가 실제 로그인/회원가입 입력 화면이나 인증 요청으로 이어지지 않는다.

## 선행 테스트 / 선행 검증

- `rg -n "href=\\\"/login|href=\\\"/signup|/login\\?|/signup\\?|로그인/회원가입|인재 탐색 시작하기" app components hooks`
- CTA 위치별 현재 이동 경로 목록 작성

## 작업

- 헤더 로그인/회원가입 링크를 데모 서버 종료 안내 모달을 여는 버튼으로 교체한다.
- 랜딩의 `인재 탐색 시작하기` CTA가 보호 라우트로 바로 가지 않도록 데모 안내/역할 선택 흐름으로 연결한다.
- `Demo 안내` 고정 버튼을 모든 페이지 좌측 하단에 추가하고, safe-area와 모바일 하단 여백을 고려한다.
- 기존 `(auth)` 페이지와 실제 `useLogin`/signup API 코드는 삭제하지 않는다.
- 운영 모드가 필요한 경우 demo mode에서만 버튼 차단/고정 버튼이 보이도록 분기한다.

## 완료 기준

- CTA 클릭 시 실제 인증 요청이 발생하지 않는다.
- 로그인/회원가입 CTA 클릭 시 `실제 로그인은 현재 제공되지 않습니다` 모달이 뜬다.
- 서버 종료 안내 모달의 `데모 페이지로 이동`은 `/demo`로 이동한다.
- `Demo 안내` 버튼은 페이지 내용을 과하게 가리지 않고 모달을 다시 열 수 있다.
