# Retrospective 프로토콜

작업 중 배운 실패 패턴은 일회성 회고로 끝내지 않고 하네스 규칙으로 승격한다.

## 기록 조건

- AI가 잘못 가정한 내용이 있었다.
- 테스트 케이스가 누락되어 뒤늦게 실패가 발견됐다.
- mock, fixture, 비동기, fetch, 상태 관리에서 반복 실수가 있었다.
- CI에서만 실패했다.
- plan/task에 없던 리스크가 구현 중 드러났다.
- drift 또는 unstuck 프로토콜이 발동했다.

## 기록 형식

```md
## <짧은 제목>

- 상황:
- 잘못된 가정:
- 영향:
- 앞으로의 규칙:
- 반영 위치:
```

## 승격 위치

- 테스트/모킹/fixture 문제: `.agents/testing.md`
- 프로젝트 구조/기술 선택 문제: `.agents/conventions.md`
- 계획/Level 판단 문제: `.agents/planning.md` 또는 `.agents/routing.md`
- 이슈/브랜치/PR 문제: `.agents/workflow.md`
- 반복 실패 대응 문제: `.agents/unstuck.md`

## 작업 종료 체크리스트

- [ ] 새로 드러난 실패 패턴이 있는가?
- [ ] 있으면 어느 `.agents/*` 문서로 승격할지 정했는가?
- [ ] 승격하지 않는다면 이유가 명확한가?
- [ ] PR 본문에 남길 리스크나 후속 과제가 있는가?

## 원칙

- 회고는 긴 보고서가 아니라 다음 작업을 덜 틀리게 만드는 규칙이다.
- 실제로 겪은 문제만 기록한다.
- 기록이 길어지면 별도 문서로 분리하고 기존 문서에는 링크만 남긴다.
