# Unstuck 프로토콜

같은 실패를 반복하면 계속 코딩하지 않고 모드 전환한다.

## 트리거

- 같은 테스트가 2회 이상 실패
- 같은 타입 에러를 반복 수정
- 계획에 없던 파일/도메인 수정이 늘어남
- 구현 중 새 구조가 계속 생김
- drift score가 0.20 이상
- 30분 이상 같은 문제에서 진전 없음

## 모드

### researcher

정보가 부족할 때 사용한다.

질문:

- 어떤 사실을 아직 확인하지 않았는가?
- 공식 문서나 기존 코드에서 확인할 수 있는 근거는 무엇인가?
- 현재 가정 중 검증되지 않은 것은 무엇인가?

출력:

```md
모드: researcher
부족한 정보:
확인할 근거:
다음 조사:
```

### simplifier

복잡도가 커질 때 사용한다.

질문:

- 지금 해결해야 하는 최소 문제는 무엇인가?
- 이번 task에서 제외할 수 있는 것은 무엇인가?
- 더 작은 커밋으로 쪼갤 수 있는가?

출력:

```md
모드: simplifier
최소 문제:
제외할 범위:
다음 작은 단계:
```

### contrarian

문제 정의나 접근이 틀렸을 수 있을 때 사용한다.

질문:

- 반대 가정이 참이면 어떻게 되는가?
- 지금 막으려는 일이 실제 문제인가?
- 아무것도 하지 않으면 어떤 비용이 생기는가?

출력:

```md
모드: contrarian
의심할 가정:
반대 접근:
판정:
```

### architect

현재 구조가 문제일 때 사용한다.

질문:

- 이 문제가 구조적 원인에서 반복되는가?
- 기존 경계와 책임을 지키고 있는가?
- 설계를 바꾸는 것이 이번 task 범위에 맞는가?

출력:

```md
모드: architect
구조적 원인:
경계 위반:
재설계 필요 여부:
```

## 원칙

- unstuck은 구현을 멈추는 신호다.
- 모드 전환 결과가 scope 변경을 요구하면 사용자 승인을 받는다.
- 새 task가 필요하면 `.agents/planning.md`에 따라 plan/task를 갱신한다.
